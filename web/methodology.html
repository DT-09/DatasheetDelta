COMPARISON METHODOLOGY

Deterministic by design.
Inspectable by default.

The system extracts explicit label/value pairs, normalizes a limited set of units and compares normalized parameter labels. It does not infer engineering intent.

01 / EXTRACTION

Read explicit fields.

CSV and XLSX inputs support two-column label/value rows, horizontal key/value pairs and tables with parameter, value and unit columns. DOCX inputs support tables and label/value paragraphs. Text-based PDF, TXT and Markdown inputs support colon-separated label/value lines.

Each field retains the source filename and row, sheet, table, paragraph, page or line location. The source excerpt is carried into the finding so a reviewer can locate the original value.

02 / NORMALIZATION

Convert only known units.

Supported conversions include selected length, pressure, voltage, current, power, frequency, mass, temperature and percentage units. Original display values remain unchanged. Numeric values are converted internally to a common base within a known dimension.

Temperature conversions apply offsets for Fahrenheit and Kelvin. Unknown units are not guessed. Incompatible dimensions are flagged for manual review.

03 / MATCHING

Match labels, not meaning.

Parameter names are lowercased, whitespace-normalized and converted to stable underscore labels. A small explicit alias map handles selected labels such as maximum pressure and rated voltage.

This is not semantic search. “Nominal pressure” and “maximum pressure” are not assumed to be equivalent. If a label appears more than once in either document, the finding is marked ambiguous rather than selecting an arbitrary row.

04 / CLASSIFICATION

Report the observed difference.

Changed
Values differ beyond the configured tolerance or text values differ.
Added / removed
A normalized parameter label exists in only one document.
Unchanged
Values match exactly or compare within tolerance after supported normalization.
Unit mismatch
Safe numeric comparison is not possible.
Ambiguous
Duplicate parameter entries require a human to resolve.

05 / LIMITS

Do not confuse extraction with completeness.

  • Scanned PDFs are not OCR-processed.
  • Complex layouts, merged cells, footnotes, diagrams and nested tables may be missed.
  • Matching is label-based and does not establish semantic equivalence.
  • A difference does not establish engineering impact, defect, safety risk or non-compliance.
  • Every result must be verified against the source by a qualified reviewer.
