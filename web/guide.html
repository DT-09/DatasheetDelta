OPERATOR DOCUMENTATION

Run a revision
investigation.

A practical guide to comparing two supplier specification revisions and reviewing the resulting evidence.

01 / BEFORE YOU START

Prepare the source files.

  • Use the original document as the reference and the later revision as the revised file.
  • Keep the files under 15 MB each.
  • Prefer explicit parameter/value tables. A separate unit column is supported.
  • Check that the selected document is the correct revision and supplier variant.
  • Do not upload restricted or confidential material unless your deployment is approved for it.

02 / RUN

Compare revisions.

  1. Open the investigation workspace.
  2. Select the reference and revised files, or load the synthetic sample.
  3. Set dimension-specific absolute tolerances only if your review procedure calls for them. Each tolerance uses that dimension's base unit; omitted dimensions are compared exactly.
  4. Run the comparison and wait for the change register.
  5. Open each evidence reference in the source document and verify it.

The tolerance is in normalized base units. It is not a percentage and not an engineering acceptance limit.

03 / INTERPRET RESULTS

Understand the status labels.

Changed
One extracted value differs from its counterpart.
Added / removed
The normalized parameter label appears in only one revision.
Unchanged
Values are identical or within the configured tolerance after supported unit conversion.
Unit mismatch
Units are missing, incompatible or unsupported for safe normalization.
Ambiguous
Multiple extracted entries share the same parameter label. Resolve them in the source.

04 / RECORD REVIEW

Capture a human decision.

Set DATASHEETDELTA_ACCESS_TOKEN on the server and enter that bearer token in the workspace. Enter the reviewer name, choose a decision and add a note. Each saved review creates a new append-only event. Events are hash-chained and checked when the investigation is reopened.

Reviewer names are self-reported. The shared-token deployment does not establish individual identity or role-based approval.

05 / EXPORT AND DELETE

Keep the record you need.

JSON export includes the findings and saved review events. CSV export includes the latest review decision for each parameter. Use the delete action to remove the stored report and its complete review history.

DatasheetDelta does not approve a design, determine engineering materiality or certify safety or compliance. Qualified engineering review remains mandatory.
